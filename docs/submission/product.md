# AgentBus Studio

AgentBus Studio is designed as an **Execution Graph OS**, not a chatbot or
generic administration dashboard. The run is the center of the product.

## Product Routes

- **Command deck**: real active, completed, failed, changed-file, provider, and
  daemon signals.
- **New run**: repository boundary validation, task composition, provider route,
  durable topology, and explicit side-effect controls.
- **Live run**: execution rail, task graph, approval gate, tool/audit timeline,
  attempt stack, source pulse, diff, verifier, final reviewer, provenance, and
  replay.
- **History**: searchable persisted durable runs.
- **Runtime**: sanitized doctor checks, provider readiness, protocol, and SSE
  transport state.
- **Payment demo**: a guided high-consequence idempotency scenario.

## Signature Components

- `ExecutionRail` presents plan, execute, verify, review, and evidence stages.
- `ApprovalGate` makes an exact paused invocation visually unmistakable.
- `AttemptStack` shows immutable attempts and corrective RetryEvidence.
- `CapabilityScope` communicates what a tool can do and where it applies.
- `SourcePulse` classifies real repository changes.
- `VerificationSeal` distinguishes mechanical evidence from review opinion.
- `EvidenceRibbon` keeps trace, provenance, replay, and call counters visible.
- `DiffViewer` renders the server-bounded repository patch.

The graphite, icy-cyan, emerald, coral, amber, and violet system assigns color
to execution semantics rather than decoration. IBM Plex Sans and Mono separate
product language from identities, commands, timestamps, and hashes.
