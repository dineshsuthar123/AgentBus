# AgentBus v0.7 release-candidate checklist

Use this checklist for one exact, reviewed candidate commit. It records local
and CI evidence; it does not execute or authorize publication. Run every gate
with live providers, public corpus downloads, external security targets,
commits, pushes, pull requests, and publication disabled unless a later,
separate workflow is explicitly approved.

## Evidence record

Use only these result labels:

- `PASS`: the required gate completed for this exact candidate.
- `PASS_WITH_WARNINGS`: the gate completed, but every bounded warning is
  recorded and accepted by a maintainer.
- `FAIL`: the gate failed or produced an unresolved safety, correctness, or
  release-blocking issue.
- `NOT_RUN`: no current-candidate evidence exists. Never infer success from a
  configured CI job, an earlier commit, or another platform.

For each item, record the result, platform, Python or Node.js version, command,
timestamp, and the location or checksum of sanitized evidence. Keep generated
reports outside tracked source files.

- [ ] Candidate branch: `________________`; status: `NOT_RUN`.
- [ ] Exact candidate commit: `________________`; status: `NOT_RUN`.
- [ ] Intended Python package and VS Code extension versions agree; status:
  `NOT_RUN`.
- [ ] The complete candidate diff and chronological commit list were reviewed;
  status: `NOT_RUN`.
- [ ] CI evidence refers to the exact candidate commit and completed jobs, not
  merely configured jobs; status: `NOT_RUN`.

## Clean installation

- [ ] Build the wheel and source distribution from the exact candidate and run
  the package-content audit; status: `NOT_RUN`.
- [ ] Install the wheel into a fresh virtual environment without an editable
  install, source-checkout import, package-index fallback, or live provider;
  status: `NOT_RUN`.
- [ ] Confirm setup, doctor, deterministic quickstart, repository indexing,
  managed read/write/test tools, approval resume, daemon restart, cancellation,
  offline replay, cleanup, uninstall, and leak checks use the installed wheel;
  status: `NOT_RUN`.
- [ ] Confirm failed-run filesystem changes remain reported for inspection and
  are not automatically reset, cleaned, deleted, or rolled back; status:
  `NOT_RUN`.

The local [RC acceptance workflow](../validation/release-candidate.md) provides
this clean-install evidence in a disposable environment. Review its report
rather than treating a zero exit code as the only evidence.

  lifecycle, and unavailable-measurement evidence; status: `NOT_RUN`.
- [ ] Run or explicitly mark `NOT_RUN` the bounded
  `agentbus soak --profile release-candidate --json` ten-minute soak; status:
  `NOT_RUN`.

- [ ] Review the platform and resource limitations documented in

## Daemon recovery and cancellation

- [ ] Confirm the owned daemon restarts with a new process, retires the old
  process, preserves event-cursor continuity, and leaves no orphan; status:
  `NOT_RUN`.
- [ ] Confirm intentional durable cancellation reaches a terminal cancelled
  state, releases leases, and does not resume terminal work; status: `NOT_RUN`.
- [ ] Confirm cancellation reporting does not promise rollback of a side effect
  that completed before cancellation was observed; status: `NOT_RUN`.

## Publication hold

- [ ] Do not tag or publish this candidate.
- [ ] Do not push, merge, rebase, create a release, upload a Python package,
  upload a VSIX, or announce the candidate as part of this checklist.
- [ ] A passing checklist is evidence for maintainer review, not authorization
  to release.
- [ ] Any future publication requires a separate explicit approval and a final
  recheck of the exact candidate commit and clean tracked worktree.
