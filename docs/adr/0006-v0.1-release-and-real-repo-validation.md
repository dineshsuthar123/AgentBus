# ADR 0006: v0.1 release surface and real-repository validation

- Status: Accepted
- Date: 2026-07-14

## Context

AgentBus had a capable runtime but was invoked from its source tree. External
developers needed standard packaging, stable commands, first-run diagnostics,
repeatable acceptance evidence, and a safe way to test representative public
repositories without adding another orchestration architecture.

## Decision

Use PEP 517 packaging around the current package layout and one imported version
attribute. Add a thin command dispatcher that forwards execution and durable
operations to the existing CLI. Build bootstrap, config, doctor, and release
report adapters around existing state, Git, provider, and evaluation APIs.

Persist repeated evaluations as immutable individual runs plus one aggregate
series containing descriptive sample statistics. Compare named run/series
references neutrally and export JSON or Markdown without selecting a winner.

Represent real repositories in a packaged, validated JSON manifest. Permit
only approved permissive SPDX licenses and exact commit SHAs. Require explicit
download and live-provider consent. Clone into marker-owned temporary storage,
verify origin and commit, copy rather than edit source, use existing durable
worktrees, and prohibit push/PR automation. Setup execution remains disabled.

## Consequences

Core installation and offline acceptance need no Azure SDK or credentials.
Config files remain explicit; AgentBus never searches upward for dotenv files.
The CLI is more discoverable without duplicating runtime logic. Real-repository
benchmarks add network, cost, and third-party-code risk, so they remain outside
normal CI. Repeated samples improve visibility but do not establish statistical
significance at small `n`.
